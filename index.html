    The rules engine for ColdBox and BoxLang

    Write rules like you speak.
    Run them like code.

    RuleBox turns tangled if/else blocks into named rules you can read, test and audit. Given some facts, when a condition holds, then act. In BoxLang, or as JSON your team can change without a deploy.

    LoanApproval.bx 
    class extends="rulebox.models.RuleBook" {

  function defineRules(){
    addRule(
      newRule( "declineLowScores" )
        .withPriority( 20 )
        .when( ( facts ) => facts.creditScore < 580 )
        .then( ( facts, result ) => result.setValue( "DECLINED" ) )
        .stop()
    )
    addRule(
      newRule( "autoApprove" )
        .when( ( facts ) => facts.creditScore >= 680 )
        .except( ( facts ) => facts.requestedAmount > 500000 )
        .then( ( facts, result ) => result.setValue( "APPROVED" ) )
    )
  }
}
    // in any handler
ruleBook( "loan" )
  .run( { creditScore: 720, requestedAmount: 250000 } )
  .getResult().getValue() // "APPROVED"

    How a rule runs

    Facts in. A decision out. Every step recorded.

    Rules run in priority order. Each one checks its condition, acts or skips, and can stop the chain. The audit trail shows exactly what happened.

    { }

    Facts

    run( facts )

    A struct of name and value pairs: the data you decide on.

    ?

    When

    .when( ... )

    Each rule tests its condition, in priority order.

    !

    Except

    .except( ... )

    An exception skips the rule even when the condition holds.

    =>

    Then

    .then( ... )

    Actions run, set the result, and can stop the chain.

    ✓

    Result

    .getResult()

    One answer, plus an audit trail of every rule.

    Natural-language DSL

    Rules read like sentences. No nested conditionals, no scattered business logic.

    given / when / except / then     {}

    Rules as data

    Load rules from JSON, YAML or a database table, with named actions and predicates.

    loadRules( source )     #

    Declared rulebooks

    Declare rulebooks in config or a folder, then get one anywhere by name.

    ruleBook( "loan" )     ≡

    Full audit trail

    Know which rules executed, skipped or failed on every run.

    getRuleStatusMap()     ◊

    Dry runs

    Ask what would happen for a set of facts, without running a single action.

    dryRun( facts )     ↕

    Priorities and stops

    Order rules explicitly and let one rule end the chain.

    withPriority( 20 ).stop()     ◷

    Time windows

    Turn a rule on for a season or a campaign, then let it expire.

    active( from, until )     ◉

    Rule Visualizer

    Dashboard, chain view, dry run, metrics and a live tracker.

    visualizer.enabled = true     ⊕

    WireBox native

    Inject rulebooks and the Builder. A fresh RuleBook per decision keeps it thread safe.

    inject="rulebook:loan"
    Code or data

    The same rule, two ways.

    Keep logic that rarely changes in BoxLang. Move thresholds that change often into JSON, YAML or a database table, and load them at runtime.
